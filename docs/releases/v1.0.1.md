# Nocturne Studio v1.0.1

`v1.0.1` is the maintenance release for the first stable release line. It
consolidates the engineering intelligence milestones delivered after `v1.0.0`,
hardens the updater and release process, and establishes
`gustavomfg/nocturne-studio` as the canonical publication and updater
repository. It does not start a new product phase.

## Highlights

- The Project Index discovers workspace structure, applies the project scope
  and exclusions, tracks file hashes, extracts supported symbols and resolves
  import/export relations incrementally.
- Change Control keeps plans, diffs, hunk decisions, execution evidence,
  validation results and rollback boundaries visible to the developer.
- Semantic Intelligence adds deterministic chunking, privacy policy,
  incremental semantic units and bounded retrieval without changing the
  approval boundary.
- Engineering Intelligence computes deterministic signals, health coverage,
  correlations, insights and trends with evidence and provenance. Missing
  coverage is reported as `not assessed`, not as a failing score.
- Update UX reports state, progress, retry and unsupported installation modes
  through the named updater bridge.
- Release and package smoke paths now validate the complete Linux, Windows and
  macOS artifact inventory before publication.

## Release hardening

- The canonical repository is `gustavomfg/nocturne-studio`. The published
  `v1.0.0` client remains compatible through GitHub's rename redirect from the
  historical `gustavomfg/Nocturne-Codex` slug; no duplicate release metadata is
  maintained.
- The updater metadata is generated for the GitHub `release` channel with
  owner `gustavomfg` and repository `nocturne-studio`.
- The transitive `js-yaml` security advisory is addressed by the existing
  `electron-updater` line and the lockfile override to `js-yaml` `4.3.2`.
- Stable release source, Codex smoke evidence, package smoke, updater
  metadata, checksums and platform inventory are verified against the exact
  tag commit. The protected environment remains responsible for Linux GPG
  signing.

## Downloads

The stable release publishes the artifacts produced by the existing
`electron-builder` targets:

- Linux: `Nocturne.Studio-Linux-1.0.1.AppImage` and
  `Nocturne.Studio-Linux-1.0.1.tar.gz`.
- Windows x64: `Nocturne-Studio-Windows-1.0.1-Setup.exe` and its
  `.exe.blockmap`.
- macOS ARM64: `Nocturne-Studio-Mac-1.0.1-Installer.dmg`, updater ZIP and
  their `.blockmap` files.
- Updater metadata: `latest-linux.yml`, `latest.yml` and `latest-mac.yml`.
- Checksums: `SHA256SUMS-Linux`, `SHA256SUMS-Windows` and
  `SHA256SUMS-macOS`.

Verify the checksum manifest that matches the platform before installing. The
Linux checksum manifest also has `SHA256SUMS-Linux.sig`, a detached GPG
signature created and verified in the protected release environment.

## Signing and updates

Linux release checksums are GPG-signed. Windows and macOS artifacts are
distributed with checksums but are unsigned and not notarized under the
current release policy; the operating system may show an additional trust
warning. No fake platform signature is supplied, and the stable workflow does
not claim stronger platform signing than the available credentials prove.

The packaged application uses `electron-updater` only after startup in a
stable build. Linux AppImage is the supported Linux auto-update target; Linux
`tar.gz` installations report auto-update as unsupported. Windows NSIS and
macOS DMG/ZIP metadata are published for their configured updater targets, but
users must respect the unsigned-platform policy and operating-system trust
prompts.

## Compatibility and known limitations

- The minimum supported Codex CLI remains `0.145.0`; `0.146.0` is the
  recommended verified version. The App Server contract is experimental and a
  newer CLI must pass the runtime compatibility handshake.
- Provider credentials remain in the operating-system secure store and do not
  enter backups, release artifacts or diagnostics.
- Review Mode remains read-only. Build Mode and Docs Mode require explicit
  approval; the application does not auto-merge, auto-refactor or act as an
  autonomous agent.
- OpenAI-compatible adapters do not normalize every provider's tool-calling
  behavior. Marketplace, cloud collaboration, multi-agent orchestration and
  future agent/Inspector integration remain outside this release.

## Validation record

The release line is validated by source, renderer, ABI, persistence, package
smoke, Codex contract and updater rehearsal workflows. Cross-platform release
packaging is performed from the exact tag SHA, and the final publication gate
rejects incomplete metadata, missing blockmaps, duplicate/unexpected assets,
version drift and checksum mismatches.
