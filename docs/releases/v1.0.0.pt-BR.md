# Nocturne Studio v1.0.0

[English](v1.0.0.md)

Estas notas descrevem o candidato `v1.0.0`. A versão está preparada no
repositório, mas ainda não é uma release estável publicada: a tag final, os
artefatos assinados e os gates protegidos ainda precisam ser concluídos.

## O que é o Nocturne Studio 1.0

O Nocturne Studio é um workspace desktop local-first de engenharia para manter
um projeto, suas conversas, evidências de revisão e conhecimento aprovado no
mesmo lugar. Ele apoia um fluxo deliberado no qual o desenvolvedor mantém a
intenção, a aprovação e a responsabilidade.

## Destaques

- Seleção e autorização explícitas do workspace, com tratamento seguro de
  workspaces movidos ou restaurados.
- Conversas persistentes, históricos paginados, estado do Git e reconciliação
  de sugestões.
- Review Mode para análise somente leitura baseada em evidências.
- Build Mode para alterações assistidas pelo Codex com aprovação, diffs visíveis
  e rollback protegido quando as precondições são atendidas.
- Docs Mode para visualizar e aplicar mudanças incrementais em Markdown com
  confirmação, verificação de concorrência e escritas atômicas.
- Segundo Cérebro e Awareness locais, com escopo, atualidade e explicação do
  conhecimento selecionado.
- Configuração de uma conta ChatGPT pelo Codex CLI/App Server e de endpoints
  remotos ou locais compatíveis com OpenAI.

## Providers e Codex

Review pode usar um Provider OpenAI-compatible. Build e Docs usam o Codex CLI e
o App Server. A versão mínima suportada do Codex CLI é `0.145.0`; `0.146.0` é a
versão recomendada e verificada. Versões mais novas precisam passar pelo
handshake de compatibilidade do App Server. O contrato do App Server continua
experimental.

As credenciais dos Providers permanecem no armazenamento seguro do sistema
operacional, ficam no processo principal e não entram em backups ou diagnósticos.

## Backup e recuperação

O estado do aplicativo fica em um banco SQLite local. O aplicativo usa
migrações transacionais, durabilidade WAL, escritas atômicas para o contexto do
workspace, snapshots antes de mudanças destrutivas e candidatos de recovery
validados. Um banco corrompido pode ser colocado em quarentena e restaurado
após confirmação do usuário quando existe um candidato válido. Esses mecanismos
reduzem o risco, mas não garantem preservação contra toda falha de hardware,
filesystem ou sistema operacional.

Arquivos do projeto não são copiados para os backups do aplicativo e as
credenciais dos Providers são deliberadamente excluídas. Faça também o backup
dos arquivos importantes pelo controle de versão ou processo de backup normal do
projeto.

## Segurança e privacidade

Isolamento do Electron, sandbox, APIs nomeadas do preload, IPC validado,
contenção de workspace e Review Mode somente leitura ficam habilitados.
Conexões remotas OpenAI-compatible exigem HTTPS e validação de endereços.
Prompts, contexto selecionado e anexos são enviados ao Provider escolhido pelo
usuário; local-first não significa que os dados enviados ao Provider ficam no
dispositivo.

## Atualizações

Aplicativos empacotados usam a política de metadados estável `release`. O
caminho `0.9.5-beta` para `1.0.0` foi ensaiado com metadados reais do updater.
Downloads são validados e exigem confirmação do usuário; downloads
interrompidos podem ser tentados novamente sem remover os dados locais. O
rollback do instalador pertence ao instalador e ao sistema operacional.

## Plataformas suportadas

A configuração de release produz:

- instalador NSIS x64 (`.exe`) para Windows 10/11;
- AppImage e `tar.gz` para Linux, na arquitetura publicada;
- DMG e ZIP do atualizador para macOS, na arquitetura publicada.

O suporte estável oficial exige os gates de assinatura, notarização e checksums
da plataforma descritos na instalação e nos documentos de prontidão.

## Limitações conhecidas

- A integração com o Codex App Server é experimental e exige um Codex CLI
  compatível e autenticado.
- Adapters OpenAI-compatible não oferecem semântica normalizada de tool calling
  em todos os endpoints.
- Não existem adapters nativos dedicados para Anthropic, Gemini ou GitHub
  Copilot neste contrato de release.
- Marketplace, colaboração em nuvem, orquestração multiagente e capacidades
  autônomas avançadas de Build/Docs estão fora do contrato da 1.0.0.

## Upgrade da 0.9.5-beta

O layout histórico de dados da `0.9.5-beta` foi ensaiado contra os caminhos
atuais de inicialização e persistência. Antes de atualizar, mantenha os backups
normais do projeto e do aplicativo recomendados para qualquer atualização. O
updater não exporta nem copia credenciais do cofre do sistema operacional. Se um
workspace foi movido, selecione e autorize novamente o novo local após iniciar.

Veja o [guia de instalação](../installation.pt-BR.md), o [guia de backup e
recuperação](../backup-and-recovery.pt-BR.md) e o [checklist do candidato de
release](../release-rc-checklist.pt-BR.md).
