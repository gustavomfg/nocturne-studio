# Nocturne Studio v1.0.1

`v1.0.1` é a release de manutenção da primeira linha estável. Ela consolida
os marcos de inteligência de engenharia entregues após a `v1.0.0`, fortalece o
atualizador e o processo de release e estabelece
`gustavomfg/nocturne-studio` como repositório canônico de publicação e
atualização. Ela não inicia uma nova fase do produto.

## Destaques

- O Project Index descobre a estrutura do workspace, aplica escopo e
  exclusões, acompanha hashes de arquivos, extrai símbolos suportados e
  resolve relações de import/export de forma incremental.
- O Change Control mantém visíveis planos, diffs, decisões por hunk,
  evidências de execução, resultados de validação e limites de rollback.
- A Semantic Intelligence adiciona chunking determinístico, política de
  privacidade, unidades semânticas incrementais e recuperação limitada sem
  alterar a fronteira de aprovação.
- A Engineering Intelligence calcula sinais determinísticos, cobertura de
  health, correlações, insights e tendências com evidência e provenance. Falta
  de cobertura é reportada como `not assessed`, não como score ruim.
- A Update UX apresenta estado, progresso, retry e modos de instalação sem
  suporte por meio da ponte nomeada do atualizador.
- Os caminhos de package e smoke agora validam o inventário completo de
  artefatos Linux, Windows e macOS antes da publicação.

## Hardening da release

- O repositório canônico é `gustavomfg/nocturne-studio`. O cliente publicado
  `v1.0.0` continua compatível pela redirect do GitHub a partir do slug
  histórico `gustavomfg/Nocturne-Codex`; não há metadados duplicados.
- Os metadados do atualizador são gerados para o canal GitHub `release`, com
  owner `gustavomfg` e repositório `nocturne-studio`.
- O advisory de segurança transitivo do `js-yaml` é tratado mantendo a linha
  existente do `electron-updater` e o override do lockfile para `js-yaml`
  `4.3.2`.
- Origem da release, evidência do smoke Codex, package smoke, metadata do
  atualizador, checksums e inventário de plataformas são verificados contra o
  commit exato da tag. O environment protegido continua responsável pela
  assinatura GPG do Linux.

## Downloads

A release estável publica os artefatos produzidos pelos targets existentes do
`electron-builder`:

- Linux: `Nocturne.Studio-Linux-1.0.1.AppImage` e
  `Nocturne.Studio-Linux-1.0.1.tar.gz`.
- Windows x64: `Nocturne-Studio-Windows-1.0.1-Setup.exe` e seu
  `.exe.blockmap`.
- macOS ARM64: `Nocturne-Studio-Mac-1.0.1-Installer.dmg`, ZIP do atualizador
  e seus arquivos `.blockmap`.
- Metadados do atualizador: `latest-linux.yml`, `latest.yml` e
  `latest-mac.yml`.
- Checksums: `SHA256SUMS-Linux`, `SHA256SUMS-Windows` e
  `SHA256SUMS-macOS`.

Verifique o manifesto de checksum correspondente à plataforma antes de
instalar. O manifesto Linux também possui `SHA256SUMS-Linux.sig`, uma
assinatura GPG destacada criada e verificada no environment protegido de
release.

## Assinatura e atualizações

Os checksums da release Linux são assinados com GPG. Os artefatos Windows e
macOS são distribuídos com checksums, mas sem assinatura e sem notarização sob
a política atual; o sistema operacional pode mostrar um aviso adicional de
confiança. Nenhuma assinatura de plataforma é inventada, e o workflow estável
não afirma uma proteção maior do que as credenciais disponíveis comprovam.

O aplicativo empacotado usa `electron-updater` somente após o startup em uma
build estável. O AppImage Linux é o alvo Linux com auto-update suportado; a
instalação Linux por `tar.gz` informa auto-update como unsupported. Metadados
Windows NSIS e macOS DMG/ZIP são publicados para os targets configurados, mas
o usuário deve respeitar a política de plataformas sem assinatura e os avisos
de confiança do sistema operacional.

## Compatibilidade e limitações conhecidas

- O Codex CLI mínimo suportado continua `0.145.0`; `0.146.0` é a versão
  recomendada e verificada. O contrato do App Server é experimental, e uma CLI
  mais nova precisa passar pelo handshake de compatibilidade.
- Credenciais de providers permanecem no cofre seguro do sistema operacional e
  não entram em backups, artefatos de release ou diagnósticos.
- Review Mode continua somente leitura. Build Mode e Docs Mode exigem
  aprovação explícita; o aplicativo não faz auto-merge, auto-refactor nem atua
  como agente autônomo.
- Adaptadores OpenAI-compatible não normalizam o comportamento de tool calling
  de todos os providers. Marketplace, colaboração em nuvem, multi-agent e a
  futura integração Agent/Inspector permanecem fora desta release.

## Registro de validação

A linha de release é validada pelos workflows de source, renderer, ABI,
persistência, package smoke, contrato Codex e updater rehearsal. O
empacotamento multiplataforma de release usa o SHA exato da tag, e o gate final
rejeita metadata incompleta, blockmaps ausentes, assets duplicados ou
inesperados, divergência de versão e mismatch de checksum.
