# Nocturne Studio v1.0.2

`v1.0.2` sucede a linha estável publicada `v1.0.1`.

## Escopo desde a v1.0.1

- Rollback protegido nos filesystems locais Linux suportados, Windows NTFS e
  macOS APFS: capabilities nativas selecionam os objetos autorizados, colisões
  preservam dados concorrentes e operações não suportadas são recusadas sem fallback fraco.
- Resultados mais claros de execução e recuperação: decisões só são concluídas
  após verificação do filesystem, falhas de preparação finalizam execuções reservadas
  e interrupções preservam evidência em vez de inventar sucesso.
- Eventos Codex isolados por turno. Reviews inválidas, falhas ou incompletas não
  podem resolver silenciosamente sugestões anteriores. O fechamento da janela
  também revoga reconnects tardios, sem reabrir uma sessão descartada.
- Validation revalida autorização do workspace/execução imediatamente antes de
  executar os comandos preparados. Isso não é um sandbox do sistema operacional.
- Invalidação mais confiável da resolução de imports, freshness conservadora de
  contexto e publicação apenas do refresh mais recente na mesma sessão do renderer.
- Descoberta de terminais Linux sem depender de `x-terminal-emulator`; nomes de
  workspace não são interpolados em comando de shell do terminal Windows. O editor
  continua usando especificamente o launcher WebStorm.
- Histórico do schema atualizado até 31 e runtime Electron atualizado para uma
  versão corrigida, além da remediação de advisories de build/teste.
- Preserva o modelo local-first, a autorização explícita do workspace e a
  fronteira de aprovação do desenvolvedor.

## Política de distribuição

Rollback não é uma transação atômica do workspace. Arquivos regulares e parents
existentes, permissões suportadas e limite de 32 MiB definem seu conjunto conservador.
Mover um diretório autorizado não revoga uma syscall já emitida; perda estrutural
conhecida impede novas admissões. Artefatos retidos e operações interrompidas podem
exigir reconciliação manual. Consulte as restrições exatas de
[rollback protegido V1](../native-rollback-v1.md).

Os alvos configurados para Linux, Windows x64 e macOS ARM64 são a fonte de
verdade dos artefatos da release. Os manifestos de checksum Linux são
assinados no ambiente de release. Os artefatos Windows e macOS são
distribuídos com checksums, mas permanecem sem assinatura e sem notarização sob
a política atual.
Auto-update macOS fica explicitamente não suportado porque o atualizador nativo
exige aplicação assinada. Atualize manualmente pelo DMG, preservando os dados
locais. Rehearsals de metadata/transporte ZIP/startup não certificam o instalador.

## Compatibilidade e limite de publicação

O CLI Codex mínimo suportado continua sendo `0.145.0`; `0.146.0` é a versão
recomendada e verificada. O contrato do App Server continua experimental, e
versões mais novas precisam passar pelo handshake de compatibilidade em tempo
de execução.

O workflow de release estável exige CI bem-sucedido para o commit da tag,
smoke dos pacotes nas três plataformas, inventário exato, metadata do
atualizador, verificação GPG Linux e checksums dos assets publicados.
