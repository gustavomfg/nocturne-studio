# Nocturne Studio v1.0.0

These notes describe the `v1.0.0` release candidate. The version is prepared
in the repository, but it is not a published stable release until the final
tag, signed artifacts and protected release gates have completed.

## What is Nocturne Studio 1.0

Nocturne Studio is a local-first desktop engineering workspace for keeping a
project, its conversations, review evidence and approved knowledge together.
It supports a deliberate workflow in which the developer retains intent,
approval and accountability.

## Highlights

- Explicit workspace selection and authorization with safe handling of moved or
  restored workspaces.
- Persistent conversations, paginated histories, Git status and suggestion
  reconciliation.
- Review Mode for read-only, evidence-backed project analysis.
- Build Mode for approved Codex-assisted changes, visible diffs and guarded
  rollback when its preconditions are met.
- Docs Mode for previewing and applying incremental Markdown changes with
  confirmation, concurrency checks and atomic writes.
- Local Second Brain and Awareness context with scope, freshness and an
  explanation of selected knowledge.
- Provider configuration for a ChatGPT account through the Codex CLI/App Server
  and OpenAI-compatible remote or local endpoints.

## Providers and Codex

Review can use an OpenAI-compatible provider. Build and Docs use the Codex CLI
and App Server. The minimum supported Codex CLI version is `0.145.0`; `0.146.0`
is the recommended verified version. Newer versions must pass the runtime App
Server compatibility handshake. The App Server contract remains experimental.

Provider credentials stay in the operating-system secure store, remain in the
main process and are not included in backups or diagnostics.

## Backup and recovery

Application state is stored in a local SQLite database. The application uses
transactional migrations, WAL durability, atomic workspace-context writes,
pre-change snapshots and validated recovery candidates. A corrupt database can
be quarantined and restored after user confirmation when a valid candidate is
available. Recovery mechanisms reduce risk but cannot guarantee preservation
against every hardware, filesystem or operating-system failure.

Project files are not copied into application backups, and provider credentials
are deliberately excluded. Back up important project files using the project's
normal source-control or backup process as well.

## Security and privacy

Electron isolation, sandboxing, named preload APIs, validated IPC, workspace
containment and read-only Review Mode are enabled. Remote OpenAI-compatible
connections require HTTPS and address validation. Prompts, selected context and
attachments are sent to the provider chosen by the user; local-first does not
mean that provider-bound data stays on the device.

## Updates

Packaged applications use the stable `release` update metadata policy. The
`0.9.5-beta` to `1.0.0` path was rehearsed with real updater metadata. Downloads
are validated and require user confirmation; interrupted downloads can be
retried without removing local data. Binary installer rollback remains the
responsibility of the installer and operating system.

## Supported platforms

The release configuration produces:

- Windows 10/11 x64 NSIS installer (`.exe`);
- Linux AppImage and `tar.gz` for the published build architecture;
- macOS DMG and updater ZIP for the published build architecture.

Official stable support requires the platform signing, notarization and
checksum gates described in the installation and release-readiness documents.

## Known limitations

- The Codex App Server integration is experimental and requires a compatible,
  authenticated Codex CLI.
- OpenAI-compatible adapters do not provide normalized tool-calling semantics
  across every endpoint.
- There are no dedicated native Anthropic, Gemini or GitHub Copilot adapters in
  this release contract.
- Marketplace, cloud collaboration, multi-agent orchestration and advanced
  autonomous Build/Docs capabilities are outside the 1.0.0 contract.

## Upgrade from 0.9.5-beta

The historical `0.9.5-beta` user-data layout was rehearsed against the current
startup and persistence paths. Before upgrading, keep the normal project and
application backups recommended for any software update. The updater does not
export or copy credentials from the operating-system vault. If a workspace was
moved, select and authorize its new location again after startup.
